    Volume mappings¶

    vp run and agent aliases accept repeatable -v/--volume options. A single absolute POSIX host path mounts at the same path with read-write access:

    vp run claude --volume /my/path
vp run claude --volume /my/path:/my/path
vp claude -v /my/path -v /host/data:/container/data:ro

    Host paths must exist. Relative paths, ~ paths, and named volumes require an explicit container destination. See Mounting volumes for modes, configured volumes, and mount restrictions.

    Workspace at its host path¶

    vp run always mounts the workspace at /workspace. Add --workspace-system-path to also mount it at its absolute host path, for tools, configs, and scripts that refer to absolute project paths:

    cd /home/alice/projects/demo
vp run claude --workspace-system-path
# Inside the container, both paths show the same files:
#   /workspace
#   /home/alice/projects/demo

    The second mount is equivalent to --volume "$PWD:$PWD" (with -w DIR, to DIR:DIR), uses the same read-write mode and SELinux handling as /workspace, and works alongside other -v/--volume options. The container still starts in /workspace. When the workspace path contains a symlink, both the resolved and the given path are mounted.

    The host path must be an absolute POSIX path; on Windows, run vp inside WSL2. VibePod rejects paths that would hide container paths it manages, such as /config, /etc, /usr, /tmp, or an agent's install directory, and a --volume whose target is the workspace host path. In --acp mode the workspace is already mounted at its host path, so the option has no effect.

    Work through vibepod-board projects with agents

    work¶

    Claim planned tasks of a board project and let an agent implement each one.

    Each task gets its own branch and a clone of the repository to work on it in. The agent runs headless with the task as its prompt; after an optional --verify command passes, the branch comes back into the repository and the task moves to Review with it. Failed and timed-out tasks go back to Planned (or blocked) with a note.

    Before each run the worker fetches the task's remote: new branches start from the remote's default branch, and a continued branch from where the remote has it when that is further along. A failed fetch goes on with the repository as it is, unless --require-fetch.

    With --mode review the worker claims tasks in Review instead, and the agent judges the work on the branch, in a clone of its own, without changing it: approve, or send it back for rework with feedback. A failing --verify command always sends it back.

    When the board asks, the worker pushes branches to GitHub from the repository with your git credentials: the commit a reviewer approved, and the branches of push requests, such as for Open PR. --no-push turns that off.

    Usage:

    vp board work [OPTIONS] {project}

    Options:

      project <str>                 Board project key, such as VP  [required]
  -a, --agent <str>             Agent that implements or reviews the tasks
                                [required]
  --mode <implement|review>     implement planned tasks, or review the tasks
                                in Review: rework or PR ready  [default:
                                implement]
  --board-url <str>             Board URL; defaults to board.url or
                                VP_BOARD_URL
  --name <str>                  Worker name on the board; defaults to
                                <agent>@<host>, or <agent>-review@<host> for a
                                review worker. Each reviewer name counts as
                                one approval
  --label <list[str]>           Only claim tasks with this label; repeat to
                                require more
  --min-readiness <int range>   Only claim tasks rated at least this ready
                                [1<=x<=10]
  --task <str>                  Work on this one task, such as VP-12, then
                                exit
  --once                        Work on one task, then exit
  --max <int range>             Exit after this many tasks  [x>=1]
  --poll <str>                  When no task is left, wait this long (30s, 5m)
                                and look again instead of exiting
  --repo <path>                 Repository to work in; defaults to the task's
                                local path
  --worktree-dir <path>         Where task clones go; defaults to
                                <repo>-worktrees next to the repository
  --base <str>                  Where new branches start, and what reviews
                                diff against, taken from the remote where it
                                is further along; defaults to the remote's
                                default branch
  --branch-template <str>       Branch name from {issue}, {number}, {key} and
                                {project}; tasks without a GitHub issue use
                                {key}, such as vp-12  [default: issue-{issue}]
  --existing <continue|refuse>  When the task's branch exists: continue or
                                refuse  [default: continue]
  --keep-worktree               Keep task clones after the hand-over or review
  --no-push                     Do not push branches for the board: neither an
                                approved one nor on request (also board.push:
                                false)
  --require-fetch               Block a task whose remote cannot be fetched,
                                instead of working from the repository as it
                                is (also board.require_fetch: true)
  --profile <str>               Credential profile to use (see `vp profile
                                list`)
  --provider <list[str]>        Temporary model provider(s) for the agent runs
  --ikwid                       Enable the agent's auto-approval flags
  --timeout <str>               Time limit per task (s/m/h), or 'none'
                                [default: 2h]
  -e, --env <list[str]>         Environment variable KEY=VALUE for the agent
  --network <str>               Additional Docker network for the agent
                                container
  --no-overlay                  Skip the project overlay image
  --verify <str>                Command that must pass in the task's clone
                                before the hand-over
  --on-fail <planned|blocked>   Where failed and timed-out tasks go: planned
                                (counts an attempt) or blocked  [default:
                                planned]
  --max-attempts <int range>    Failed attempts before a task is blocked
                                [x>=1]
  --parallel                    Run alongside other workers on the same
                                profile
  --usage-limit-wait <str>      Pause after a usage limit when the agent names
                                no reset time  [default: 30m]
